# Project Overview

## Overview

In this project, you will design, implement, and evaluate a small-scale agentic AI system using the agent design and orchestration techniques you developed in your Nanodegree. You will define a clear use case, build an agent or small agentic workflow that combines reasoning, limited memory, and tool use, and evaluate how the system performs on realistic tasks while accounting for reliability, transparency, and safety considerations.

This project uses only the tools you already know:

* Python
* Agentic AI frameworks or patterns covered in your coursework
* OpenAI API access or equivalent course-approved interfaces
* Jupyter Notebooks or Python scripts

You are building an agentic system in this project. The focus is on correct workflow design, thoughtful integration of tools and memory, and responsible system behavior rather than building a production-ready application.

## Why This Project Matters

Agentic AI systems introduce system-level challenges beyond single-model development. Employers expect professionals to:

* Design agents with clearly defined roles, goals, and boundaries
* Integrate reasoning, memory, and tool use into coherent workflows
* Handle errors, uncertainty, and edge cases safely
* Add safeguards that promote transparency, reliability, and responsible use
* Evaluate agent behavior using realistic tasks and failure analysis
* Communicate design decisions and limitations clearly

This project develops the system-thinking and governance mindset required to deploy agentic AI responsibly and prepares you for integrative and industry-facing AI work later in the capstone.

## What You Will Build

You will create:

* An agent implementation (agentic\_system.ipynb or agentic\_system.py) that:
  + defines the agent’s purpose, scope, and boundaries
  + integrates reasoning logic, limited memory or state, and at least one tool
  + executes multi-step tasks using an agentic workflow
  + includes logging, safeguards, or transparency mechanisms
  + documents key design choices and observations using Markdown or comments
* An Agentic AI System Report (module\_summary.pdf) that explains:
  + the use case and why an agentic approach is appropriate
  + the agent’s design, including persona, decision logic, memory, and tools
  + how safeguards for reliability, transparency, or misuse prevention were implemented
  + evaluation results, including strengths and failure cases
  + limitations, ethical considerations, and potential improvements
    This report must include in-text citations and a References section.

## Citation Expectations

In your Agentic AI System Report, you must use citations when you:

* refer to agentic AI concepts or definitions (for example: agent roles, orchestration patterns, tool calling, memory design, or evaluation methods)
* justify architectural or workflow design choices
* discuss safeguards, transparency practices, or responsible-use considerations

You do not need to cite your own code, logs, or agent outputs that come directly from your implementation and test runs. Your report must end with a References section listing all sources used, such as course materials, textbooks, or official documentation.

## Academic Integrity Expectations

This project is designed to require authentic, individual work:

* The agent and workflow must be implemented and executed by you.
* Evaluation must reference your own test tasks and observed agent behavior.
* Safeguards and transparency measures must reflect what you actually implemented.
* Design and ethical reasoning must be grounded in your specific system and results.

Generic descriptions of agent behavior or safety practices not tied to your implementation will not meet project expectations.

# Environment Setup

## Local Machine Instructions

Before you begin the project, make sure your environment is set up correctly. This will help you avoid errors and ensure your agentic AI notebook or script runs smoothly from start to finish.

1. Install Python 3.x
   You can use any recent version of Python 3 (3.9 or higher).
2. Install a development environment
   You may use any of the following:

* Jupyter Notebook
* JupyterLab
* VS Code with the Jupyter Extension
* Anaconda (includes Jupyter by default)

3. Install required Python libraries
   Make sure the following core libraries are installed:

* NumPy
* Pandas
* Matplotlib

Depending on your agent design, you may also use Python-based agent frameworks, APIs, or utilities that were explicitly covered in the Agentic AI course materials. No new tools outside the course are required.

If you are using Anaconda, many of these libraries may already be available.

## Validate Your Environment

1. Open a new Jupyter Notebook or Python script.
2. Run the following code to confirm the core libraries import correctly:
   import numpy as np
   import pandas as pd
   import matplotlib.pyplot as plt
3. If your agent uses an LLM framework or API covered in the course, verify that the required credentials or local configurations are accessible according to course guidance.
4. Run a small test cell or script that executes a minimal agent step (for example, a single reasoning or tool-use action) to confirm your environment is functioning correctly.

If the imports run without errors and your test execution succeeds, your environment is ready.

## Create Your requirements.txt File

Before submitting your project, generate a reproducibility file from your environment:

pip freeze > requirements.txt

This file allows others to rerun your agentic workflow using the same package versions.

## Project 6 — Agentic AI Systems

Design of Autonomous or Semi-Autonomous Agents, Workflows, and Safeguards

## What You Will Submit

* agentic\_system.ipynb or agentic\_system.py
* Agentic\_AI\_System\_Design\_Report.pdf
* requirements.txt

## Project Instructions

### Task 1 — Define the Agentic Task and System Scope

For this project, you will define an agentic AI task and design a small-scale agent or agentic workflow using methods covered in the Agentic AI coursework. Clearly defining the task, scope, and boundaries of the agent is part of the assessment.

You must clearly describe:

* The goal of the agent or workflow
* Whether the system is single-agent or multi-agent
* What decisions the agent is responsible for
* What actions or tools the agent can use

The task should require reasoning, decision-making, and at least one form of tool use or external interaction.

#### System Requirements

Your agentic system must:

* Be implementable using tools and frameworks covered in the Agentic AI course
* Include explicit reasoning or decision logic
* Include limited memory, state, or context handling
* Use at least one tool, function, or external capability
* Be appropriate for academic use
* Not reuse an agent or workflow from a previous capstone project

Clearly document the intended behavior and boundaries of the system.

### Task 2 — Design the Agent Architecture

Before implementation, design the structure of your agent or workflow.

Your notebook or script must include:

* A clear description of the agent’s components (persona, reasoning loop, memory, tools)
* An architecture diagram or structured description of how components interact
* A brief explanation of design choices and tradeoffs

This ensures the system is intentionally designed rather than ad hoc.

### Task 3 — Implement the Agent or Workflow

Implement your agent or agentic workflow using approved course tools.

Your implementation must include:

* Agent initialization and configuration
* Reasoning or decision logic
* Memory or state handling appropriate to the task
* Tool or function invocation logic
* Safeguards such as constraints, checks, or fallback behavior

The system does not need to be production-ready, but it must execute as intended.

### Task 4 — Execute and Observe Agent Behavior

Run your agent on representative inputs or scenarios.

Your notebook or script must include:

* Example runs of the agent
* Observable outputs or actions produced by the agent
* Notes on how the agent reasons through decisions
* At least one example of a limitation, failure case, or unexpected behavior

This demonstrates real system behavior rather than hypothetical design.

### Task 5 — Write a Short Notebook or Script Summary

Add a brief Markdown section (4 to 6 sentences) summarizing:

* The agent’s purpose and design
* Key behaviors observed during execution
* Any challenges encountered
* Known limitations or risks

This concludes your implementation artifact.

### Task 6 — Write the Agentic AI System Design Report (with Academic Citations)

Create Agentic\_AI\_System\_Design\_Report.pdf with the following sections.

#### Overview

Explain the agentic task, system goal, and overall approach.

#### System Architecture and Design

Describe the agent’s components, reasoning flow, memory handling, and tool use. Include or reference your architecture diagram.

#### Decision Logic and Behavior

Explain how the agent makes decisions and how it responds to different inputs or situations.

#### Safety, Reliability, and Transparency

Discuss safeguards, constraints, and design choices intended to improve reliability, interpretability, or transparency.

#### Observed Behavior and Limitations

Analyze actual agent behavior based on your runs, including failure cases or limitations.

#### Ethical and Responsible Use Considerations

Identify at least one ethical concern related to autonomy, misuse, bias, accountability, or societal impact, grounded in your system’s design and behavior.

#### Future Improvements

Describe realistic next steps that could improve robustness, safety, or capability.

#### Citation Requirements

Use citations when:

* Defining agentic AI concepts or architectures
* Justifying design patterns or safeguards
* Discussing ethical, governance, or responsible-use considerations

Do not cite your own code or execution outputs.

#### References

List all cited sources using a consistent citation style.

### Task 7 — Create requirements.txt

Generate your reproducibility file using:

```
pip freeze > requirements.txt
```

This ensures the agentic AI system can be rerun in an identical environment.
